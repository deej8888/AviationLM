AeroLM / Methodology overview
01 / TRAINING AND EVALUATION

Teach a small model a specific task.

Read an aviation request and produce the required JSON structure.

AeroLM.
  1. Prepare 1,000 synthetic email-to-JSON examples.Correct labels come from sampled facts, not the rules extractor.
  2. Keep the original Qwen3-0.6B weights frozen.Train 10.1 million LoRA adapter parameters alongside them.
  3. Predict JSON, compare with the target, and update LoRA.Three epochs, 375 optimizer updates; 120 validation requests monitor loss.
  4. Save the adapter and evaluate generated answers.120 held-out test requests plus 24 challenge cases; compare rules, base Qwen, and tuned Qwen.
  5. Measure validity and extraction quality.Precision, recall, F1, and entirely correct requests.
Existing frozen weights Trainable adapter / saved artifact

Low training loss shows learning on the examples. Held-out extraction results tell us whether that learning is useful.

All fine-tuning examples in this project are synthetic.1 / 2
02 / USING THE TRAINED MODEL

Turn a new request into a reviewable record.

The base model and saved adapter work together on each request.

AeroLM.
  1. Provide a new charter request.The application combines it with extraction instructions and the JSON schema.
  2. Run the saved Qwen model and LoRA adapter together.The model generates an answer; it does not retrain for each email.
  3. Check strict JSON and schema validity.Invalid output is rejected. Valid structure alone does not prove correct facts.
  4. Have staff review the draft.Confirm airports, dates, passengers and preferences; resolve unknowns.
  5. Potential future integration: prefill a quotation or operations record.This business-system connection is not implemented in the prototype.

The practical goal is less retyping and a consistent draft record, with a person confirming the operational details.

Charter extraction is the implemented domain; other domains need their own data and schemas.2 / 2
